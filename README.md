# linux-log-triage

Локальный Python CLI для учебной первичной сортировки **переданных пользователем текстовых Linux-журналов**. Работает с файлами на Windows 10/11 и Linux, без Linux API и внешних зависимостей во время анализа. Требуется Python 3.10+.

Результат — индикатор для ручной проверки. Несколько ошибок входа сами по себе не доказывают компрометацию. Программа не устанавливает факт взлома и не принимает мер против пользователей или адресов.

## Установка и запуск: Windows PowerShell

Из каталога проекта, после установки Python 3.10+:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-deps .
New-Item -ItemType Directory -Force reports | Out-Null
.\.venv\Scripts\linux-log-triage.exe examples\synthetic.log --mask --output reports\demo.json
.\.venv\Scripts\linux-log-triage.exe 'C:\Lab\auth.log' --year 2026 --timezone '+03:00' --window-seconds 300 --threshold 3 --mask --format csv --output reports\auth.csv
.\.venv\Scripts\linux-log-triage.exe 'C:\Lab\journal.txt' --mask --format markdown --output reports\journal.md
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Активация окружения и изменение ExecutionPolicy не нужны. Файлы Linux заранее копируются пользователем на Windows. Приложение не подключается к Linux-хосту.

## Установка и запуск: Kali Linux

```bash
sudo apt update
sudo apt install python3 python3-venv
python3 -m venv .venv
.venv/bin/python -m pip install --no-deps .
mkdir -p reports
.venv/bin/linux-log-triage examples/synthetic.log --mask --output reports/demo.json
.venv/bin/linux-log-triage ./auth.log --year 2026 --timezone '+03:00' --mask --format markdown --output reports/auth.md
.venv/bin/python -m unittest discover -s tests -v
```

Для самого анализатора `sudo` не требуется. Установка пакета может скачивать средства сборки через pip; **во время анализа** сетевых операций нет. Возможен запуск без установки: PowerShell `$env:PYTHONPATH = 'src'`, затем `python -m linux_log_triage ...`; Linux `PYTHONPATH=src python3 -m linux_log_triage ...`.

## Как заранее получить файл на Linux

Это отдельные команды, которые пользователь выполняет самостоятельно на Linux с нужными правами. Анализатор их не вызывает и не читает системный журнал напрямую.

```bash
umask 077
# Все сообщения за выбранный период; даты замените нужными.
sudo journalctl --since '2026-10-26 00:00:00' --until '2026-10-27 00:00:00' --no-pager --output=short-iso-precise > journal.txt
# Либо копия обычного журнала (путь зависит от конфигурации системы).
sudo cat /var/log/auth.log > auth.log
# Для систем, использующих secure:
sudo cat /var/log/secure > secure.log
```

Выберите необходимый способ, затем передайте полученный файл анализатору. Экспорт может превышать установленный лимит; ограничьте период заранее. **Журналы и отчёты могут содержать чувствительные данные**: IP, имена, пути, команды и аргументы. Не публикуйте реальные журналы. Пример `examples/synthetic.log` полностью вымышленный, использует документационный IP `192.0.2.10`.

## Правила и объяснения

| Правило | Распознаваемое условие |
| --- | --- |
| `ssh_failed` | Сообщение `sshd`: `Failed <method> for [invalid user] <user> from <IP>` |
| `ssh_invalid_user` | Сообщение `sshd`: `Invalid user <user> from <IP>` |
| `ssh_success` | Сообщение `sshd`: `Accepted <method> for <user> from <IP>` |
| `sudo_command` | Сообщение `sudo`: `<actor> : ... USER=<target> ; ... COMMAND=<command>` |
| `sudo_session` | `sudo: pam_unix(sudo:session): session opened/closed for user <target>` |
| `repeated_event` | Не менее `--threshold` одинаковых событий за `--window-seconds` секунд; по умолчанию 3 за 300 секунд |

Валидируются IPv4 и IPv6. `Failed ... for invalid user` создаёт одну запись `ssh_failed` с `unknown_user=true`, а не два события. Отдельная строка `Invalid user` остаётся отдельным событием: количество сообщений **не равно количеству попыток**. Счётчик `unknown_user_events` включает обе формы.

Группировка повторов: один исходный файл, правило, IP, пользователь, инициатор sudo, команда и действие сессии. События с датой сортируются по UTC. Начало окна включительно; его длительность не превышает заданную. Используются жадные непересекающиеся окна: от самого раннего события берутся все следующие в пределах окна; при достижении порога они образуют группу, затем поиск продолжается после неё. Это ограничивает объём доказательных ссылок. Все возможные перекрывающиеся окна не перечисляются. События без распознанной даты учитываются в сводке, но исключаются из временной группировки. Разные файлы не объединяются, повторный путь входного файла отклоняется. Дубли сообщений внутри файла не удаляются.

Для каждого события терминал и экспорт содержат ID источника, номер строки и условие правила. Повторы содержат список номеров строк, фактическое количество и границы времени. Успех после ошибок отображается отдельно; такая последовательность требует контекстной проверки и не получает автоматического вердикта. По умолчанию терминал не выводит IP, пользователей, команды или полные строки. Он перечисляет объяснения всех распознанных событий, поэтому на больших файлах вывод может быть длинным.

## Даты и кодировки

- Поддержаны ISO 8601 с `T` или пробелом, секундами, дробными секундами, `Z`, `+03:00` или `+0300`; в том числе текстовый `journalctl -o short-iso-precise`.
- Для старого syslog `Oct 27 10:15:00 host ...` задайте `--year`: это год **первой** записи. Переход Dec→Jan повышает год. Файл должен идти в календарном порядке для такого восстановления года; перемешанные записи и многолетние выборки требуют заранее нормализованных ISO-дат.
- Для времени без зоны используется `--timezone`, по умолчанию **UTC**, не локальная зона машины. Поддержаны только фиксированные смещения; DST и IANA-названия не поддержаны. Для точной группировки экспортируйте даты с явным смещением.
- Некорректные даты, отсутствующий год и leap-second `:60` не восстанавливаются догадками. Событие сохраняется без времени, выводится диагностический счётчик.
- `--encoding auto`: UTF-8 (с BOM или без), UTF-16 при наличии BOM, включая обычный вывод Windows PowerShell 5.1. Для CP1251 и других текстовых кодировок используйте `--encoding cp1251` и т. п. Автоматического угадывания legacy-кодировок нет.
- Ошибки декодирования заменяются; строки с символом замены или NUL пропускаются с диагностикой. Строки длиннее 65536 символов также пропускаются. Остальные неизвестные непустые строки считаются `unrecognized_lines`, без классификации.

## Локальный экспорт и приватность

```bash
linux-log-triage ./auth.log ./secure.log --year 2026 --max-mib 10 --mask --format json --output reports/combined.json
linux-log-triage ./journal.txt --encoding utf-8 --mask --format csv --output reports/events.csv
linux-log-triage ./auth.log --year 2026 --include-raw --format markdown --output reports/private-evidence.md
```

JSON содержит настройки, источники, счётчики, диагностику, события, повторные окна и условия правил. CSV содержит типизированные записи `notice`, `settings`, `summary`, `privacy`, `source`, `diagnostic`, `events`, `repetitions`. Markdown представляет те же основные данные для чтения человеком. Все экспорты записываются в UTF-8. CSV защищает текстовые поля от формул таблиц, Markdown экранирует пользовательский текст.

Полные строки включаются **только** через `--include-raw` и только в экспорт. Без маскировки экспорт содержит распознанные IP/имена, абсолютный путь источника и команды sudo. `--mask` присваивает последовательные псевдонимы `ip-1`, `user-1` в пределах одного запуска, убирает пути, команды и полные строки, даже если указан `--include-raw`. Таблица соответствий не сохраняется. Время, номера строк и корреляция псевдонимов сохраняются: это не гарантия полной анонимности. Условия правил состоят из фиксированного текста; для исходной строки используйте локальный исходный файл и её номер.

Файлы открываются только для чтения. Допускаются `.log`, `.txt`, а также имена `secure` и `syslog`; входные каталоги, glob-обход, архивы и автоматический поиск отсутствуют. Лимит по умолчанию **10 MiB суммарно**, максимум настройки 100 MiB; проверяются как размер перед открытием, так и фактически прочитанные байты. Лимит ограничивает вход, но не является лимитом всей памяти процесса. Программа работает со снимком прочитанных байтов, не следит за изменениями файла. Выход создаётся только по явному `--output`, существующие файлы и входные пути не перезаписываются; родительская папка должна существовать. Экспорты защищайте правами доступа вашей ОС. Код возврата 0 означает завершённый анализ (включая пустой файл или предупреждения), 2 — ошибку входа/параметров/записи; число индикаторов не влияет на код возврата.

В приложении нет сетевого клиента, отправки журналов, вызовов `journalctl`, изменения событий, блокировок адресов, генератора сторонних отчётов или парсера Nmap XML. Экспорт относится только к локальному результату triage.

## Ограничения первой версии

- Это эвристики конкретных сообщений, не универсальный syslog/PAM-парсер и не инструмент расследования.
- Не поддержаны бинарные `.journal`, сжатые/ротированные архивы, JSON/JSON-seq/export/verbose/short-monotonic/short-unix форматы journalctl, auditd, Nmap XML, Windows Event Log, локализованные и многострочные сообщения.
- SSH: не распознаются произвольные PAM authentication failure, disconnect, max-auth-tries, ban, `sshd-session`, сообщения без `sshd:`/`sshd[PID]:` или без числового IP. Повторы встроенной формы `last message repeated N times` не разворачиваются.
- Sudo: произвольные отказы, JSON sudo, нестандартные PAM-модули и изменённые форматы не распознаются; команда остаётся свободным текстом. Отдельные сообщения отказа и продолжения строки не склеиваются.
- Предполагается один хост на входной файл. Имя хоста и PID не входят в ключ повторов: смешанные центральные сборники предварительно разделите по хостам.
- Несколько файлов могут содержать одно событие; общая сводка считает строки каждого файла, без межфайловой дедупликации. Нет оценки достоверности источника и обнаружения подделки журналов.

## Тесты и проверенная среда

```bash
python -m unittest discover -s tests -v
```

Вымышленные данные покрывают SSH/sudo, IPv4/IPv6, временное окно и границу окна, успех после ошибок, разные даты и смещения, Dec→Jan, високосный год, отсутствующие даты, сортировку, пустые и повреждённые файлы, UTF-8/UTF-16/CP1251, ограничения размера, маскировку, экранирование экспорта и запрет перезаписи. `.github/workflows/tests.yml` запускает тесты и CLI на Windows и Ubuntu с Python 3.10/3.12/3.14.

Первоначальная локальная проверка: Windows, Python 3.14. Kali Linux локально не проверялась. Ubuntu в GitHub Actions не считается тестом Kali; статус CI смотрите в Actions репозитория.
